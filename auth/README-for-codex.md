# S2: усиленный сервис входа — готовый код, не черновик

Это полная замена папки `auth/` в репозитории `messenger-server` по итогам
отчёта `docs/reports/T22-Claude.md`. Код написан и проверен Claude; Codex
нужно только применить файлы, обновить два соседних файла по инструкции
ниже и прогнать тесты.

## Что изменилось и почему (коротко)

- Раньше при пустом `WA_APP_SECRET` сервис принимал подтверждения номеров
  без проверки, кто их прислал. Теперь без секрета сервис не запускается
  (кроме `DEV_MODE=true` для локальной проверки).
- Сессии и история запросов хранятся в SQLite (`db.py`), а не в памяти —
  переживают перезапуск контейнера.
- Добавлен лимит запросов на один IP-адрес, отдельно от уже имевшегося
  лимита на номер.
- Если Synapse на момент выдачи пароля не ответил, подтверждённая сессия
  не пропадает — можно повторить запрос статуса без нового кода.
- Протокол (`/auth/start`, `/auth/status/{sid}`, `/auth/webhook`,
  `/auth/dev/message`, `/auth/health`) не менялся: поля запросов и ответов
  те же, приложение (Flutter) трогать не нужно.

## Как проверено

Прямым вызовом функций `app.py` с лёгкими заглушками вместо FastAPI/httpx
(сеть не использовалась) и с настоящим `sqlite3`: 16 проверок, все прошли —
включая обязательность секрета при старте, лимиты по номеру и по IP, то,
что сбой Synapse не теряет сессию, и то, что данные читаются другим
процессом из того же файла (имитация перезапуска). Полный протокол в
`docs/reports/T22-Claude.md`.

Файл `test_app.py` — это настоящие тесты на pytest + httpx (ASGI), их я
писать-то написал, но прогнать не смог: в моей среде нет интернета, чтобы
поставить fastapi/httpx/pytest. **Пожалуйста, прогони именно этот файл** —
это более полная проверка, через настоящий HTTP-слой, а не через прямой
вызов функций.

## Что сделать (порядок)

1. В репозитории `messenger-server`, в новой ветке (например `auth-hardening`):
   заменить `auth/app.py`, добавить `auth/db.py`, `auth/test_app.py`,
   `auth/pytest.ini`, `auth/requirements-dev.txt`; заменить `auth/Dockerfile`
   на вариант из этого пакета (отличие: копирует ещё и `db.py`).
2. Применить изменения `docker-compose.yml` и `.gitignore`, описанные в
   `docker-compose.patch.md`.
3. В `.env.example` сменить `DEV_MODE=true` на `DEV_MODE=false` и добавить
   комментарий про обязательность `WA_APP_SECRET` (текст в том же файле).
4. Прогнать тесты:
   ```
   cd auth
   pip install -r requirements.txt -r requirements-dev.txt
   python3 -m pytest test_app.py -v
   ```
   Все тесты должны пройти. Если что-то красное — прислать полный вывод,
   не пытаться чинить вслепую больше двух раз подряд.
5. Собрать образ (`docker compose build auth`) и локально проверить:
   `docker compose up -d auth` при пустом `.env` (без `WA_APP_SECRET`,
   `DEV_MODE=false`) должен **остановиться с понятной ошибкой** в логах —
   это ожидаемое поведение, не баг.
6. Открыть Pull Request, в описании сослаться на `docs/reports/T22-Claude.md`
   и на этот файл, приложить вывод тестов.
7. Отчёт о проделанном — в `docs/reports/S2-codex.md` (или следующий номер
   по вашей нумерации), по вашему обычному формату.

## Что не входит в этот пакет
